The authoritative inventory table enforces allocated <= capacity, alongside nonnegative capacity and allocation checks (schema.sql:1-6). This database boundary protects both enabled writers, including the nightly import (schedule.json:1).

The importer uses an unconditional increment (jobs.py:20-24), but this is not an overselling path: an increment beyond capacity violates the CHECK constraint, the transaction context rolls back, and the importer catches IntegrityError and returns False (jobs.py:19-28). This matches the contract’s rejected-order outcome. Even sequential API/import activity cannot bypass the shared invariant; concurrent database writes do not remove the constraint.
